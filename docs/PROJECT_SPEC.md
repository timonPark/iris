# Iris 프로젝트 기획 정리

대화로 확정한 내용을 기록한 문서입니다. (작성일: 2026-11-17)

## 1. 개요

웹과 모바일 앱의 채팅 화면에서 질문을 입력하면 백엔드가 이 PC에서 실행 중인 Hermes(Nous Research 에이전트)에 전달하고, Hermes의 답변을 스트리밍으로 화면에 표시하는 서비스입니다.

```
[웹 / iOS / Android] → [FastAPI 백엔드] → [Hermes API 서버]
                              ↓
                        [PostgreSQL]
```

- 이 PC의 Hermes에 인터페이스를 가진 누구든 연결할 수 있어야 합니다.
- 백엔드가 모든 사용자의 유일한 입구입니다.
- 질문은 프론트 → 백엔드 → Hermes 순서로 가고, 답변은 같은 경로로 돌아와 화면에 표시됩니다.

## 2. 구성 요소와 기술 스택

| 구성 | 기술 | 비고 |
|---|---|---|
| 백엔드 | Python, FastAPI | 공통 API + 클라이언트 전용 엔드포인트 |
| 웹 (사용자) | Vite + React | 채팅 화면 |
| 관리자 웹 | 별도 웹 (`admin/`) | 사용자 관리 전용 |
| 모바일 | Flutter | iOS와 Android 모두 |
| DB | PostgreSQL | docker-compose로 실행 |

### 저장소 구조 (모노레포)

```
iris/
├── backend/
├── web/
├── admin/
├── mobile/
├── docs/
└── docker-compose.yml   # PostgreSQL만 포함
```

- 웹과 모바일은 세션 두 개로 동시에 개발합니다.
- 두 세션이 어긋나지 않도록 구현 전에 API 규격을 먼저 설계합니다.

## 3. 이번 스프린트 범위

1. 텍스트 채팅 (웹, 모바일): 질문 입력 → Hermes 답변 스트리밍 표시
2. 모바일 음성 입력
3. 관리자 웹: 사용자 등록, 차단, 비밀번호 초기화
4. 인증 (아이디/비밀번호 + JWT)

다음 스프린트로 미룬 것: 구글 문서/시트/슬라이드 링크 처리

## 4. Hermes 연동

- **연결 방식**: Hermes API 서버 (HTTP + SSE 스트리밍, OpenAI 호환)
  - `POST /v1/chat/completions` (stream), `POST /v1/responses`
- **대상**: 기본 프로필 (기존 기억, 도구, 구글 드라이브 연동을 그대로 사용)
- **API 서버 키**: 백엔드만 보관하고 사용자에게 노출하지 않음
- **주의**: API 서버는 기본으로 꺼져 있어 `API_SERVER_ENABLED`, `API_SERVER_KEY` 설정 후 게이트웨이 재시작이 필요함 (구현 단계에서 별도로 진행)
- **주의**: 기본 프로필을 쓰므로 이 프로젝트의 대화가 기존 Hermes 세션과 섞일 수 있음

## 5. 음성 입력 처리 (모바일)

```
녹음 → 백엔드로 업로드 → 형식 변환(ffmpeg) → 음성 인식(whisper.cpp)
     → 맞춤법 보정(Claude 헤드리스) → 화면 표시 + Hermes 전송 → 음성 파일 삭제
```

- **음성 인식**: whisper.cpp + `ggml-large-v3-turbo`
  - 실행 파일: `/opt/homebrew/bin/whisper-cli`
  - 모델: `~/.whisper-models/ggml-large-v3-turbo.bin`
  - 형식 변환: 설치된 `ffmpeg`
- **맞춤법 보정**: Claude 헤드리스(`claude -p`), 가벼운 모델 사용
  - 맞춤법, 띄어쓰기, 명백한 오인식만 고치고 내용은 바꾸지 않음
  - 도구 권한은 모두 막음
- **화면 표시**: 보정된 텍스트만 표시하고, 수정 단계 없이 바로 Hermes로 전송
- **음성 파일**: 변환이 끝나면 바로 삭제
- 음성 업로드는 모바일 전용 엔드포인트로 둠

## 6. 인증과 관리자

- **방식**: 아이디/비밀번호 + JWT
- **역할**: 관리자, 일반 사용자
- **계정 생성**: 관리자가 직접 등록 (사용자 화면에 가입 기능 없음)
- **관리자 웹 기능**: 사용자 등록, 차단, 비밀번호 초기화 (대화 열람은 포함하지 않음)
- 관리자 API는 사용자 API와 경로를 분리하고, 백엔드가 관리자 권한을 반드시 검사함

## 7. 데이터 저장

- **DB**: PostgreSQL (docker-compose, PostgreSQL만 컨테이너로 실행)
- 백엔드, 웹, 관리자 웹은 PC에서 직접 실행 (whisper, Claude, Hermes 접근을 그대로 쓰기 위해)
- **대화 기록**: 우리 DB에 저장
- **계정**: 아이디, 비밀번호 해시, 역할, 활성/차단 상태

## 8. 외부 접속

- ngrok 사용 (HTTPS 제공, 공유기 설정 불필요). 무료 플랜이 계정마다 고정 개발 도메인(`*.ngrok-free.dev`)을 주므로 터널을 껐다 켜도 주소가 같다. (Cloudflare Quick Tunnel은 시작할 때마다 주소가 바뀌어서 쓰지 않는다.)
- 무료 한도(월 HTTP 요청 2만 건, 월 전송 1GB)에 가까워지면 ngrok 유료 플랜이나 본인 도메인과 Cloudflare Named Tunnel로 바꾼다. 사용자 공개 전에 도메인 연결을 검토
- 터널과 백엔드는 PC 부팅 시 자동 실행되도록 구성
- PC가 꺼져 있는 동안은 접속 불가이며, 켜지면 같은 주소로 다시 접속됨
