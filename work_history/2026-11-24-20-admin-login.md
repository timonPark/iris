### 확인 방법과 결과
- `npm test` 24개 통과, `npm run lint`·`npm run build` 오류 없음.
- 실제 백엔드: 이 PC에 임시 백엔드를 띄우고 사용자 `viewer01`, 차단된 사용자 `blocked01`을 관리자 API로 만든 뒤, `VITE_API_BASE_URL=http://127.0.0.1:8010 npm run dev`로 붙여 Chrome headless(playwright-core)로 확인.
  - 틀린 비밀번호 → 백엔드 401 → "아이디 또는 비밀번호가 올바르지 않습니다."(규격 문구), 저장 없음
  - 사용자 계정 → 백엔드 200(role user) → "관리자 계정만 로그인할 수 있습니다.", 저장 없음
  - 차단된 사용자 계정 → 백엔드 403(`ACCOUNT_BLOCKED`) → 같은 문구, 저장 없음
  - 관리자 → 200 → 관리자 화면(머리글 "Iris 관리자"와 아이디), `sessionStorage`에만 저장(`localStorage` 비어 있음)
  - 새로고침해도 관리자 화면, 같은 브라우저의 새 탭은 로그인 화면
- 완료 조건 1(샘플과 같은 화면): 샘플의 `login-not-admin`과 나란히 스크린샷 비교. 제목, 부제 "관리자 웹", 안내 상자, 입력칸, 로그인 버튼의 배치와 색이 같다. 안내 상자가 조금 더 높은 것은 Primer `Flash` 기본 여백이며 사용자 웹 로그인과 같다. 라이트·다크·좁은 화면(375px) 스크린샷도 눈으로 확인.
- 완료 조건 2(관리자 역할이 아닌 계정은 로그인 불가): 위의 사용자, 차단된 사용자 결과.
- Aside 브라우저 확인(사용자 요청): 같은 임시 백엔드에 붙인 `http://localhost:5174/`을 Aside에서 열어 같은 시나리오를 다시 했다. 틀린 비밀번호 → 규격 문구, 사용자·차단된 사용자 → "관리자 계정만 로그인할 수 있습니다.", 셋 다 `sessionStorage`와 `localStorage`에 저장 없음. 백엔드 로그는 401, 200, 403, 200 순서. 관리자 → 머리글 "Iris 관리자 / e2eadmin", `sessionStorage`에만 저장. 새로고침해도 유지, 새 탭은 로그인 화면. 375px에서 머리글 아이디가 숨고(샘플과 같음) 로그인 화면 제목이 한 단계 작아짐. 스크린샷을 눈으로 확인.
- 한계: 원격 서버(ngrok)의 관리자 계정은 비밀번호를 몰라 확인하지 못했다.
