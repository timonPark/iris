## 작업 내용

관리자 API는 사용자 API와 경로를 분리하고, 백엔드가 관리자 권한을 반드시 검사한다.

### 범위
- [x] 관리자 역할만 호출 가능, 대상은 사용자 역할 계정만
- [x] 사용자 계정 목록(나눠서 호출, 검색 없음)
- [x] 등록(아이디 입력 → 시스템이 임시 비밀번호를 만들어 응답에 한 번만 담음)
- [x] 차단, 해제
- [x] 비밀번호 초기화(임시 비밀번호 생성, 한 번만 응답, 이전 토큰 무효, 임시 비밀번호 상태로 표시)

제외: 관리자 계정 등록·차단, 계정 삭제, 계정 검색, 대화 열람

### 완료 조건
- [x] 관리자가 아닌 계정이 호출하면 거부된다.
- [x] 관리자 계정을 대상으로 한 요청은 거부된다.
- [x] 등록·초기화 응답에만 임시 비밀번호가 있고 이후 조회로는 알 수 없다.

## 설계 (Claude가 정함)
- 규격(`docs/api/openapi.yaml`)의 `/api/v1/admin/users` 5개를 그대로 구현한다. DB 스키마 변경은 없다(마이그레이션 없음).
- **권한 검사는 라우터 전체에 건다.** `/api/v1/admin` 라우터에 `require_admin` 의존성을 라우터 수준으로 걸어서, 앞으로 이 경로에 만드는 API가 검사를 빠뜨릴 수 없게 한다. 그리고 "이 경로 아래의 모든 라우트가 `require_admin`에 의존한다"를 테스트로 지킨다(새 라우트를 추가하면서 검사를 잊는 것을 막음). 관리자가 아닌 계정은 403 `FORBIDDEN`.
- 대상은 **사용자 역할 계정만**이다. 관리자 계정을 대상으로 하거나(자기 자신 포함) 없는 계정, UUID가 아닌 값은 모두 같은 404 `USER_NOT_FOUND`(관리자 계정의 존재 여부도 알려 주지 않음).
- 임시 비밀번호: `secrets`로 만든 읽기 쉬운 12자(헷갈리는 `0 O 1 l I` 제외, 약 68비트). 응답에 한 번만 담고 DB에는 argon2 해시만 저장한다. 두 응답(등록, 초기화)에는 `Cache-Control: no-store`를 붙인다. 로그에도 남기지 않는다.
- 등록: 새 계정은 역할 사용자, 상태 활성, 임시 비밀번호 상태. 아이디가 이미 있으면(관리자 아이디 포함) 409 `LOGIN_ID_TAKEN`이고, 두 요청이 동시에 같은 아이디를 등록하는 경쟁도 유일 제약으로 409로 처리한다.
- 차단과 해제는 이미 그 상태여도 200(멱등). 토큰은 그대로 두고 계정 상태만 바꾸며, 요청마다 상태를 검사하는 #16의 구조 덕분에 다음 요청부터 거부된다.
- 초기화: 임시 비밀번호를 새로 만들고 `password_changed_at`을 갱신해(이전 토큰 모두 무효) 임시 비밀번호 상태로 만든다. 차단 상태는 그대로 둔다. 사용자가 동시에 비밀번호를 바꾸는 경우와 순서대로 처리되도록 행을 잠근다(#17과 같은 방식).
- 목록은 사용자 역할 계정만, 차단된 계정도 포함, 최신 등록 순, 위치 기준 커서(`keyset_page`, 범위 `admin-users`). 규격에 목록 API의 `422`(잘못된 `limit`, `cursor`)가 빠져 있어 규격에 먼저 추가했다.

### 확인 방법과 결과
- 전체 테스트 284개 통과.
- 변이 검사 14가지를 하나씩 넣어 모두 테스트가 잡음(권한 검사 제거, 관리자 대상 허용, 임시 비밀번호 저장/로그 노출, 토큰 무효화 제거, 차단 상태 변경, 행 잠금 제거, 중복 처리 등). 11번은 "중복이면 해시를 하지 않는다"가 동작은 같아 처음엔 못 잡았고 테스트를 추가해 잡도록 함. 14번(`secrets` 사용)은 테스트 기대값이 틀려 `TEMPORARY_PASSWORD_ALPHABET[0] * 12`로 고침.
- 실제 서버 + 개발 DB + 실제 관리자 계정으로 전 과정 확인: 등록 201(`no-store`, 12자), 임시 비밀번호 로그인 → 일반 API 403 → 변경 후 200, 일반 사용자 관리자 API 403, 목록에 관리자 없음, 차단(살아 있던 토큰 즉시 403)/해제, 초기화(이전 토큰·옛 비밀번호 401, 새 임시 비밀번호 200), 관리자 대상 404, 중복 409, 규칙 위반 422. 서버 로그에 임시 비밀번호/해시 0건. 임시 계정 삭제 후 개발 DB에는 `admin`만 남음.
- 완료 조건 3개 모두 충족: 비관리자 거부, 관리자 대상 거부, 임시 비밀번호는 등록·초기화 응답에만 있음.
