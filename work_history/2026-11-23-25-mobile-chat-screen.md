### 사용자와 정한 것 (2026-11-23)
- 답변 중 연결이 끊기면(모바일 앱이 백그라운드로 가거나 네트워크가 바뀜): 받은 부분까지 두고 "연결이 끊겼습니다. 답변은 서버에서 계속 저장됩니다."라고 안내한다. 모바일 앱이 다시 앞으로 오면 그 세션을 다시 불러와, 저장이 끝났으면 전체 답변을 보여준다. 아직이면 안내가 남고 세션을 다시 열면 볼 수 있다. `ssot/GLOSSARY.md` "답변"에 반영.

### 이번에 정한 것 (Claude가 정함, 사용자 웹 #24를 따름)
- 화면 틀: 샘플처럼 위쪽 막대(메뉴 버튼, 제목)와 본문, 세션 목록은 서랍(폭은 화면에서 큰 컨트롤 하나만큼 뺀 값). 설정은 서랍 아래의 "설정"으로 본문 자리에 연다(#19의 임시 채팅 자리와 위에 여는 설정 화면은 지움). 새 세션 버튼은 샘플과 웹처럼 없다(모바일 앱을 새로 열면 새 세션).
- 새 세션이 목록에 생기는 때, 중지를 켜는 때, 다른 세션을 열어도 받던 답변을 끝까지 읽는 것, 옛 세션을 100개씩 끝까지 받아 오래된 순으로 보여주는 것, 65,536자 검사(코드 포인트), 문구("질문은 65,536자까지 보낼 수 있습니다.", "다시 시도", 서버 오류는 "…잠시 후 다시 질문해 주세요.")는 사용자 웹(#24)과 같다.
- 빈 화면 안내는 녹음 버튼이 아직 없어 웹 문구("지난 대화는 세션 목록에서 볼 수 있습니다.")를 쓴다. 샘플의 "입력하거나 녹음 버튼을 눌러 말해 보세요."와 입력이 비었을 때의 녹음 버튼은 #32에서 넣는다.
- 연결 끊김의 다시 불러오기: 서버의 질문 수가 화면에서 저장된(또는 저장될) 질문 수 이상이면 저장이 끝난 것으로 보고 바꾼다. 아니면 안내를 둔다.
- 스레드는 아래에서부터 쌓는 스크롤(reverse)로, 맨 아래를 보고 있으면 답변을 따라 내려간다.
- 설정의 위쪽 막대 왼쪽은 샘플의 메뉴 버튼 대신 "채팅으로 돌아가기"(뒤로) 버튼이다. 저장된 세션이 없으면 설정에서 채팅으로 돌아올 길이 없어서다(codex 리뷰). 기기의 뒤로 가기도 같다.
- 지금 세션을 목록에서 다시 누르면 다시 불러오지 않는다(받던 답변을 잃지 않게, codex 리뷰).

### 코드 리뷰
- codex(`codex review --uncommitted`): 5건 모두 반영(각각 테스트 먼저)
  - 반영: 첫 답변이 저장 전에 끊긴 뒤 이어서 물으면 세션 ID 없이 보내 새 세션이 됨 → 끊긴 답변의 세션을 지금 세션으로 둠
  - 반영: 저장된 세션이 없으면 설정에서 채팅으로 돌아올 길이 없음 → 설정에서는 위쪽 막대에 "채팅으로 돌아가기"(뒤로) 버튼, 기기의 뒤로 가기도 같게
  - 반영: 로그인이 풀려 화면이 사라진 뒤에도 받던 스트림이 없어진 컨트롤러를 부름 → `ChatController.dispose`에서 구독을 끊고 늦은 결과를 버림, 세션 목록도 없어진 뒤 알리지 않음
  - 반영: 삭제를 기다리는 중 대화상자를 닫으면 성공해도 목록에 남음 → 닫혔어도 성공이면 목록에 반영
  - 반영: 답변 중인 지금 세션을 목록에서 다시 누르면 다시 불러오며 받던 답변과 중지 버튼을 잃음 → 지금 세션은 다시 불러오지 않음
- agy(`agy -p`, 전체 diff): 11건
  - 반영: 다른 세션에서 받던 답변이나 보내는 중이던 질문이 나중에 저장되면 지운 세션이 목록에 되살아남(구독이 하나만 남는 것, 보내는 중 삭제 두 지적) → 세션 목록이 지운 세션을 기억해 다시 올리지 않음
  - 반영: 끝 이벤트(`done`/`stopped`/`error`)를 받아도 연결이 닫혀야 받는 중이 끝남 → 끝 이벤트에서 바로 끝냄
  - 반영: 다음 페이지가 중복뿐이면 목록 길이가 그대로라 이어 불러오기가 멈춤 → 목록 끝 표시를 불러온 횟수로 새로 만듦
  - 반영: `Colors.transparent` → `bgColorTransparent` 토큰, 콜백 매개변수 타입 명시 3곳(`(Object? _)`, `(BuildContext _)`, `(Duration _)`)
  - 반영: 테스트 보강 — 보고 있는 세션 삭제 시 빈 새 세션, 삭제 실패 시 대화상자에 오류, 돌아와서 다시 불러오기 실패 시 다음에 다시 시도(셋 다 처음부터 통과)
  - 넘어감: `ChatController.dispose` 없음 → codex 반영에서 이미 고침(agy는 반영 전 diff를 봄)
  - 넘어감: 스트리밍 중 `error` 이벤트로 온 `ACCOUNT_BLOCKED`·`UNAUTHORIZED`를 로그인 처리하지 않음 → 규격에서 인증 검사는 스트리밍 시작 전 일반 오류 응답이고, SSE `error`는 답변 중 오류(Hermes 등)라서 이 경우가 없다
