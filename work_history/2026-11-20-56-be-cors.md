## 작업 내용

사용자 웹과 관리자 웹을 다른 PC에서 개발할 때(브라우저의 `http://localhost:5173` 등) 이 PC의 백엔드(ngrok 고정 도메인)를 호출할 수 있게 CORS를 설정한다. 모바일 앱은 영향이 없다.

### 범위
- [x] `localhost`, `127.0.0.1`의 모든 포트를 기본 허용, 추가 주소는 설정(`CORS_ALLOW_ORIGINS`, 쉼표로 구분)
- [x] 사전 요청(preflight), 실제 요청, 오류 응답, SSE 응답에 CORS 헤더
- [x] ngrok 경유 확인(안내 페이지가 사전 요청을 막지 않는지)

제외: 배포된 웹 주소 확정(웹을 공개할 때 설정으로 추가)

### 완료 조건
- [x] 허용한 주소에서 오는 사전 요청과 실제 요청(오류 응답과 SSE 포함)에 CORS 헤더가 붙는다.
- [x] 허용하지 않은 주소에는 CORS 헤더가 붙지 않는다.
- [x] 외부 주소(ngrok)를 통해서도 사전 요청이 통과한다.

### 결정 필요
없음 (Claude가 정함)

## 설계 (Claude가 정함)
- 인증은 `Authorization: Bearer` 헤더라서 쿠키를 쓰지 않는다 → 자격 증명 허용(`Access-Control-Allow-Credentials`)은 켜지 않고, `*`도 쓰지 않는다(허용한 주소를 그대로 돌려준다).
- 허용 주소: 기본은 `localhost`와 `127.0.0.1`의 모든 포트(Vite가 포트를 바꿔도 되게). 그 밖의 주소(공개한 웹 주소 등)는 `backend/.env`의 `CORS_ALLOW_ORIGINS`에 쉼표로 적는다.
- 허용 헤더: `Authorization`, `Content-Type`, `ngrok-skip-browser-warning`. 메서드는 API가 쓰는 `GET POST DELETE`와 사전 요청의 `OPTIONS`.
- 구현은 Starlette의 `CORSMiddleware`를 앱에 추가한다.

## 결과

### 변경한 파일

- 문서: `backend/CLAUDE.md`(CORS 절)

### 확인 방법과 결과
- 전체 테스트 390개 통과. `test_cors.py`: 허용 주소(localhost 여러 포트, 127.0.0.1)의 사전 요청과 헤더, GET/POST/DELETE, 허용하지 않은 주소(`https://evil.example`, `localhost.evil.example`, `null` 등)에는 헤더 없음, 오류 응답(401, 422)과 500에도 헤더, `Origin`이 없는 요청은 그대로, `CORS_ALLOW_ORIGINS`로 추가한 주소 허용.
- 처음 테스트에서 처리하지 못한 오류(500)에는 CORS 헤더가 붙지 않는 것을 찾았다(브라우저에서는 서버 오류 내용을 못 읽고 CORS 오류로만 보임). 테스트를 먼저 쓰고 오류 처리기가 헤더를 붙이게 고쳤다.
- 실제 서버(launchd로 다시 시작)와 외부 주소(ngrok)에서 브라우저 User-Agent로: 허용 주소의 사전 요청 200과 CORS 헤더(ngrok 안내 페이지가 막지 않음), 실제 요청(401 오류 응답)에 `access-control-allow-origin`, 허용하지 않은 주소에는 헤더 0개.
- 한계: 실제 브라우저(다른 PC의 웹)에서의 호출은 확인하지 못했다(curl로 브라우저 요청을 흉내 냄).

### 코드 리뷰 반영 내역 (`/code-review medium`)
- 반영(테스트 먼저): 앱을 만들기만 해도 `POSTGRES_*` 설정을 요구하게 된 문제(CORS 설정만 읽는 `CorsSettings`로 분리) / 500 경로와 미들웨어의 허용 기준 통일(`fullmatch`, 끝의 `/` 제거, `*` 무시) / 500 응답의 `Vary` 덮어쓰기(추가로 변경) / `https://localhost`와 `[::1]` 허용 / 이름만 SSE였던 테스트를 실제 SSE(실제 소켓) 테스트로 교체, 추가 주소가 500 경로에도 적용되는지 테스트.
- 넘어감: 500 헤더를 오류 처리기가 직접 붙이는 구조(미들웨어 재구성이 이 변경에 비해 크고 테스트로 고정함), 허용 요청 헤더 고정 목록(우리 API가 쓰는 헤더만, 필요하면 추가), 개발용 localhost 허용을 환경 플래그로 묶기(개발 단계라 항상 허용).
