## 진행 기록

- 2026-11-24 브랜치와 작업 파일 생성. 선행 이슈 #10 닫힘 확인. Hermes는 원격 PC에 있어 이 PC에서는 설정 파일을 볼 수 없다. 원격 백엔드(ngrok)의 채팅 API로 Hermes에 질문해 확인하기로 함.

- 2026-11-24 질문 스크립트(비밀번호를 숨겨 입력받고 답변만 파일로 저장)를 만들어 사용자가 자기 계정으로 실행. 질문 2개(도구와 권한, 파일 찾기)를 같은 세션으로 보냄. 저장소가 공개라 개인 정보(계정 메일, 파일 이름, 파일 ID)를 빼고 이슈에 댓글을 씀. 원본 답변은 저장소에 넣지 않음.
- 2026-11-24 확인 중 사용자가 웹에 새 세션 버튼이 없다고 지적 → 범위 밖이라 #72(에픽), #73([fe]), #74([mobile])로 등록. 사용자가 나중에 진행하기로 함.
- 2026-11-24 사용자와 다시 정리: 실제로 필요한 흐름은 "Hermes가 가진 자료를 드라이브에 올리고 그 주소를 돌려주는 것"이다. 이 확인은 개인 드라이브에 파일을 만들므로 후순위로 빼서 백엔드 이슈 #75에서 하기로 하고, 이 이슈는 1차 확인(도구와 권한, 검색으로 URL 반환, 링크 모양)으로 마무리. 이슈 본문의 범위를 그에 맞게 적음.
- 2026-11-24 사용자 확인 후 머지. 상태 `완료`.

## 결과

### 확인 방법
- 원격 Iris 백엔드(ngrok)에 사용자 계정으로 로그인해, 앱과 같은 `POST /api/v1/sessions/questions`(SSE)로 기본 Hermes에 질문. 두 질문 모두 "조회만 하고 만들거나 고치지 말 것"을 붙임. 답변 14초, 18초. 이벤트는 `session`, `delta`, `done`.

### 결과 요약 (자세한 것은 이슈 댓글)
- 가능하다. Hermes는 `google-workspace` 스킬(터미널의 `google_api.py`)로 드라이브 검색과 메타데이터 조회를 하고, 실제로 검색해 URL을 답변에 넣어 돌려줬다. 추가 설정은 필요 없다.
- 토큰 scope: `drive`, `documents`, `spreadsheets`, `forms.body`, `calendar`, `gmail.modify`, `gmail.send`, `gmail.readonly`, `contacts.readonly`.
- 링크는 마크다운이 아닌 맨 URL로 온다. 받은 것은 시트 `https://docs.google.com/spreadsheets/d/<ID>/edit` 2개. 문서와 슬라이드 URL은 직접 보지 못했다(#38, #39 전에 한 번 더 확인 권장).
- 위험: 토큰에 드라이브 삭제·공유, 메일 보내기 권한이 있고 Iris 사용자 누구나 시킬 수 있다. Hermes가 기억의 개인 정보를 답변에 말했다.
