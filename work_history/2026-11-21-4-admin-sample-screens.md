### 검토에서 정할 것
1. 사용자 계정이 관리자 웹에 로그인하면 막는다(로그인 응답의 `role`이 `user`면 토큰을 저장하지 않음). 문구 "관리자 계정만 로그인할 수 있습니다." 정하면 `ssot/GLOSSARY.md`의 "관리자 웹"에 반영한다. 백엔드는 관리자 API를 `FORBIDDEN`으로 막으므로, 이것은 화면 안내다.
2. 로그아웃: 사용자 웹처럼 넣지 않았다(#3에서 정함). 관리자 웹은 공용 PC에서 쓸 수 있어 따로 정해야 한다.
3. 페이징: 커서 방식이라 페이지 번호 없이 "더 보기" 버튼으로 20개씩 이어 받는다. 전체 수는 API가 주지 않아 보여주지 않는다.
4. 확인 대화상자: 차단과 비밀번호 초기화는 확인을 받고, 차단 해제는 바로 한다.
5. 임시 비밀번호 화면: "지금만 볼 수 있다"는 노란 안내, 아이디와 임시 비밀번호(고정폭 글꼴), "복사" 버튼, "전달했습니다"로 닫는다. 등록과 초기화가 같은 화면을 쓴다.
6. 목록 칸: 아이디, 상태(활성/차단 중), 비밀번호(임시 비밀번호/설정함), 등록일, 작업(차단 또는 차단 해제, 비밀번호 초기화). 최근 등록 순.
7. 새로 쓴 문구: "관리자 웹"(로그인 부제), "관리자 계정만 로그인할 수 있습니다.", "Iris 관리자", "사용자 계정", "계정 등록", "등록한 사용자 계정이 없습니다" 안내, "영문 소문자와 숫자 4~20자", "비밀번호는 시스템이 만들어 다음 화면에 한 번만 보여 줍니다.", "계정을 등록했습니다", "비밀번호를 초기화했습니다", "임시 비밀번호는 지금만 볼 수 있습니다. 창을 닫기 전에 사용자에게 전달해 주세요.", "사용자는 이 비밀번호로 로그인한 뒤 바로 새 비밀번호로 바꿔야 합니다.", "전달했습니다", 차단·초기화 확인 문장, "서버 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.", "다시 시도", "설정함". 오류 문구 자체("이미 사용 중인 아이디입니다." 등)는 `openapi.yaml`의 `message`를 그대로 썼다.

### 확인 방법과 결과
- 토큰 검사(#3의 스크립트): 샘플의 `<style>`에서 쓴 `var(--…)` 102개가 모두 `@primer/primitives@11.10.0`에 있다. 값을 직접 쓴 곳은 컨테이너 쿼리 조건 `48rem` 한 곳뿐이다(CSS 변수를 쓸 수 없어 `--breakpoint-medium`과 같은 값, 주석). hex 색은 없다.
- 렌더링 확인: Chrome headless(playwright-core)로 화면 11개 × 라이트/다크 × 넓은 화면/좁은 화면, 모두 44장을 찍어 눈으로 확인했다. 콘솔 오류와 실패한 요청은 없었고, 다크에서 화면 배경은 `rgb(13, 17, 23)`(Primer dark `bgColor-default`)였다. 좁은 화면에서는 표가 계정마다 한 장씩 쌓인다.
- Aside 브라우저 확인(사용자 요청): Aside는 `file://`을 열 수 없어서 `python3 -m http.server 8766`으로 띄운 `http://127.0.0.1:8766/index.html`에서 확인했다(끝나고 서버를 멈춤).
  - Primer CSS가 불러와지는지: `--bgColor-default`가 라이트 `#ffffff`.
  - 44개 조합(화면 11개 × 라이트/다크 × 넓은 화면/좁은 화면): 주소의 화면 이름, 테마, 프레임 너비(넓은 화면 / 320px), 배경색(라이트 `rgb(255,255,255)`, 다크 `rgb(13,17,23)`)이 모두 맞고, 프레임 밖으로 넘치는 요소가 없다.
  - 동작: 로그인 → 목록, 계정 등록 → 등록 대화상자, 등록 → 임시 비밀번호(제목 "계정을 등록했습니다"), 전달했습니다 → 목록, 차단 → 차단 확인, 확인의 차단 → 목록, 비밀번호 초기화 → 초기화 확인, 초기화 → 임시 비밀번호(제목 "비밀번호를 초기화했습니다"), 취소 → 목록. 임시 비밀번호 대화상자의 이름(`aria-labelledby`)이 화면마다 맞게 바뀐다.
  - 키보드: "계정 등록"에서 Tab을 누르면 첫 행의 "jhpark 차단" 버튼으로 가고 포커스 테두리(2px solid `rgb(9,105,218)`)가 보인다. 작업 버튼 이름에 아이디가 들어 있다("jhpark 비밀번호 초기화", "leesy 차단 해제" 등).

### 코드 리뷰 반영 내역
- codex(`codex review --uncommitted`): 지적 없음.
- agy(`agy -p`, diff를 프롬프트에 넣음): 17건
  - 반영: 임시 비밀번호 값에 `aria-labelledby`가 있어 스크린 리더가 값 대신 "임시 비밀번호"만 읽음 → 지움
  - 반영: `<label>` 하나에 입력칸 2개(아이디 중복 화면의 입력칸이 라벨과 연결되지 않음) → 화면마다 label을 나눔
  - 반영: 표의 아이디 칸을 행 머리글(`th scope="row"`)로
  - 반영: 복사 버튼 이름을 "임시 비밀번호 복사"로
  - 넘어감: `--breakpoint-xsmall`이 없는 토큰. 토큰 검사에서 있음을 확인했다(#3 샘플도 같은 토큰).
  - 넘어감: `.btn--danger:disabled` 테두리. danger용 비활성 테두리 토큰이 없어 default 것을 쓴다(#3과 같음).
  - 넘어감: 표(label)에 배경색이 없다. Primer Label처럼 테두리와 글자색만 쓰는 모양이다(#3의 "중단됨"과 같음).
  - 넘어감: 자간에 `--base-size-2`. 자간 토큰이 없어 가장 작은 크기 토큰을 쓴다.
  - 넘어감: `button, input`에 `font: inherit`. 버튼과 입력칸은 각자 `font`를 정한다(#3과 같음).
  - 넘어감: "차단 해제", "더 보기"를 눌러도 화면이 바뀌지 않음. 해제는 확인 없이 그 행만 바뀌는 동작이고, 정적 샘플이라 화면을 따로 두지 않았다.
  - 넘어감: 등록 뒤 목록으로 돌아가면 새 행이 사라짐. 정적 샘플의 화면 전환 한계다.
  - 넘어감: 좁은 화면에서 아이디와 작업 칸에 이름(data-label)이 없다. 아이디는 카드 제목이고 작업은 버튼이라 이름이 필요 없다.
  - 넘어감: 해제 완료, 목록 끝, 아이디 형식 오류, 로그인 실패 화면. 해제는 행만 바뀌고, 목록 끝은 "더 보기"를 숨기며, 형식 오류와 로그인 실패는 같은 자리에 규격의 문구가 나온다(샘플 도구 설명에 적음).
