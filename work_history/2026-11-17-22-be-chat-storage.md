## 작업 내용

대화 기록은 우리 DB에 저장한다. 세션 흐름을 다시 보기 위한 기록이며, 맥락 전달의 기준이기도 하다.

### 범위
- [x] 세션, 질문, 답변 저장 모델. 답변 상태는 완료와 중단됨
- [x] 세션은 첫 질문을 보내는 순간 생성(빈 세션은 만들지 않음). 표시 이름은 첫 질문 앞 30자 정도
- [x] 세션 목록 조회(나눠서 호출), 세션 열람(질문·답변을 나눠서 호출), 본인 세션만 접근
- [x] 세션 삭제: soft delete. 삭제하면 목록과 열람에서 보이지 않고 복구·영구 삭제는 없다. 세션 단위로만 삭제
- [x] 질문 길이 65,536자 초과 거부

제외: 세션 이름 변경, 관리자의 대화 열람

### 완료 조건
- [x] 세션 생성, 목록, 열람, 삭제 API 테스트가 통과한다.
- [x] 다른 사용자의 세션에 접근할 수 없다.
- [x] 삭제한 세션이 목록과 열람에서 보이지 않고 DB에는 남아 있다.

### 결정 필요
- [x] 삭제된 세션에 질문을 보냈을 때의 응답: 기본안대로 **없는 세션으로 처리**(404 `SESSION_NOT_FOUND`).
- [x] 세션 목록의 정렬 기준: 기본안대로 **최근 활동 순**(`updated_at` 내림차순, 같으면 `id`).

## 설계 (Claude가 정함)
- 이 이슈에서 **질문을 보내는 엔드포인트(`POST /sessions/questions`)는 만들지 않는다.** Hermes 호출과 SSE는 #23이다. 이 이슈의 "세션 생성"은 #23이 쓸 저장 서비스(`save_exchange`)로 만들고 그 서비스를 테스트한다. 만드는 API는 규격의 `GET /api/v1/sessions`, `DELETE /api/v1/sessions/{sessionId}`, `GET /api/v1/sessions/{sessionId}/questions` 세 개다.
- 테이블: `chat_sessions`(`id`, `account_id` FK, `title`, `created_at`, `updated_at`, `deleted_at`), `questions`(`id`, `session_id` FK, `text`, `created_at`), `answers`(`id`, `question_id` FK 유일, `text`, `status` completed/stopped, `created_at`). 세션 모델 이름은 SQLAlchemy의 `Session`과 겹치지 않게 `ChatSession`이다. 질문과 답변은 용어집대로 별개의 용어이고, 한 질문에 답변은 하나다(저장은 한 트랜잭션).
- 질문은 답변과 함께 저장한다(#23: Hermes 호출이 실패하면 질문도 세션도 저장하지 않음).
- 삭제는 `deleted_at`만 채운다(soft delete). 삭제된 세션과 다른 사용자의 세션은 목록·열람·삭제·질문 저장 모두 "없는 세션"(404)이다.
- 목록은 위치 기준(keyset) 커서로 나눠서 호출한다. 커서는 `(시각, id)`를 base64로 담은 값이고 클라이언트는 해석하지 않는다. 잘못된 커서는 422 `VALIDATION_FAILED`. 세션 열람(질문 목록)은 최신 질문부터.
- 질문 길이 규칙(65,536자 초과 → 422 `QUESTION_TOO_LONG`, 빈 질문 → 422 `VALIDATION_FAILED`)은 #23의 엔드포인트가 쓸 함수로 만든다.
- 응답 모델의 공통 기반(`ApiModel`)은 두 번째 사용처가 생겨 `app/schemas.py`로 옮긴다(이전 리뷰에서 미뤄 둔 항목).

### 코드 리뷰 반영 내역
지적 10건 중 8건 반영, 2건 넘어감.
- 반영(진짜 버그): 질문에 NUL 문자나 UTF-8로 바꿀 수 없는 문자가 있으면 저장 단계에서 DB 오류(실제로는 500). 테스트로 재현(`DataError`)한 뒤, 질문은 422로 거부하고 이미 Hermes가 답한 **답변은 문제 문자만 정리해서 저장**(NUL은 지우고 나머지는 `\ufffd`)해 답변을 잃지 않게 함
- 반영(진짜 버그): 커서의 극단적인 시각 값(`0001-01-01T00:00:00+14:00` 등)이 DB로 가서 500. UTC로 바꿀 때 범위를 벗어나면 422로 처리
- 반영: 세션 목록의 커서를 질문 목록에 쓰거나 다른 세션의 커서를 쓸 수 있던 문제. 커서에 범위(`s`)를 담아 다르면 422
- 반영: 최근 활동 시각이 뒤로 갈 수 있던 문제. DB에서 `GREATEST`로 원자적으로 갱신
- 반영: 목록용 인덱스를 삭제 제외 부분 인덱스(`WHERE deleted_at IS NULL`)로 변경. 삭제는 영구적이고 행이 지워지지 않아 삭제가 쌓일수록 목록이 느려지는 문제
- 반영: 두 목록에 복사되어 있던 커서 페이징 코드를 `keyset_page()` 하나로 합침(위 수정이 한 곳에서 적용됨), 변수 타입 표기
- 반영: 규격의 커서 설명에서 "누락이 없다"를 정확하게 고침(아래 넘어감 참고)
- 반영: 이 작업 파일의 리뷰 내역, 상태 갱신
- 넘어감: 세션 목록이 최근 활동 순이라 페이지를 넘기는 사이 새 질문이 와서 맨 위로 올라간 세션은 그 순회에서 빠질 수 있다는 지적. 바뀌는 값으로 정렬하는 목록의 본질적 특성이라 코드는 그대로 두고, 규격이 과하게 말한 부분만 고침(처음부터 다시 호출하면 보임)
- 넘어감: 답변 없는 질문이 있으면 열람이 500이라는 지적. 질문은 `save_exchange`로만 저장되고 항상 답변과 함께 만들어지며(테스트로 지킴), #23이 저장 방식을 바꾸면 그쪽에서 모델과 규격을 함께 고쳐야 함. 한 행 때문에 조용히 건너뛰거나 숨기지 않음
