## 작업 내용

이전 세션을 연 뒤 빈 새 세션으로 돌아갈 방법이 새로고침뿐이다. 사이드바에 [새 세션] 버튼을 만든다.

범위: 사이드바에 [새 세션] 버튼. 누르면 빈 새 세션 화면이 되고 다음 질문부터 새 세션이 된다. 설정 화면에서도 누르면 채팅으로 돌아온다. 좁은 화면에서는 서랍을 닫는다. 백엔드 API 변경은 제외(`sessionId` 없이 질문하면 이미 새 세션이 만들어진다).

완료 조건
- [x] 이전 세션을 연 뒤 [새 세션]을 누르면 빈 화면이 되고, 다음 질문이 새 세션으로 저장되어 목록 맨 위에 생긴다.
- [x] 이전 세션에는 그 질문이 들어가지 않는다.

### 확인 방법과 결과
- `npm test` 75개 통과, `npm run lint`·`npm run build` 오류 없음, 30줄 넘는 함수 없음.
- headless Chrome(실제 백엔드와 DB, 가짜 Hermes): 확인용 계정 `web73user`로
  - 첫 질문 → [새 세션] → 제목 "새 세션", 두 번째 질문은 새 세션
  - 지난 세션을 연 뒤 [새 세션] → 제목 "새 세션", 화면의 지난 질문 0개 → 세 번째 질문은 새 세션. 목록 `세번째, 두번째, 첫` 순. **DB(세션별 질문 API)로 세션마다 자기 질문 하나씩만 있는 것을 확인**(지난 세션에 섞이지 않음)
  - 긴 답변을 받는 중 [새 세션] → 화면은 바로 빈 새 세션, 그 답변은 끝까지 받아 목록에 생기고 DB에 `completed`(534자)
  - 빈 새 세션에서 입력 중 [새 세션] → 입력 "쓰는 중" 그대로
  - 설정에서 [새 세션] → 채팅의 "새 세션"
  - 375px 서랍에서 [새 세션] → 서랍 닫힘
  - 라이트·다크·서랍 스크린샷을 눈으로 확인
- Aside 브라우저: 확인용 탭(5176)을 따로 열어 지난 세션 → [새 세션] → 질문(새 세션으로 목록 맨 위), 답변 중 [새 세션] → 화면은 새 세션, 답변이 끝나 목록에 생김. 스크린샷을 눈으로 확인하고 탭을 닫음.
