## 작업 내용

이 PC의 백엔드(포트 8000)를 ngrok 무료 플랜의 고정 개발 도메인으로 외부에 연다. 터널을 껐다 켜도 주소가 같아서 모바일 앱이 같은 주소를 계속 쓸 수 있다.

### 범위
- [x] ngrok 설치와 계정 설정(설치 완료: `brew install --cask ngrok`, 3.39.13)
- [x] 무료 개발 도메인을 백엔드 포트(8000)에 연결
- [x] 사용자 웹·관리자 웹·모바일 앱의 서버 주소 설정 방법 정리(프로젝트가 아직 없어서 각 프로젝트 세팅 이슈에서 적용)
- [x] 무료 한도(월 HTTP 요청 2만 건, 월 전송 1GB) 확인 방법과 전환 기준 정리

제외: 도메인 구입

### 완료 조건

- [x] SSE 스트리밍 답변이 터널을 통해 끊기지 않고 표시된다.
- [x] 대시보드에서 요청 수와 전송량을 확인하는 방법이 적혀 있다.

## 설계 (Claude가 정함)
- 도구는 이슈 본문대로 ngrok이다(Cloudflare Quick Tunnel은 시작할 때마다 주소가 바뀜). `docs/PROJECT_SPEC.md` §8의 Cloudflare 기술을 ngrok 기준으로 고친다.
- 실행은 `ngrok http --url=<고정 도메인> 8000`. 인증 토큰은 ngrok 자체 설정 파일(`~/Library/Application Support/ngrok/ngrok.yml`)에만 두고 저장소에는 넣지 않는다. 도메인 이름은 비밀은 아니지만 개인 계정 값이라 저장소 문서에는 `<고정 도메인>`으로 적는다.
- 부팅 시 자동 실행은 #35에서 한다.

## 결과

### 변경한 파일
- `docs/PROJECT_SPEC.md`(§8을 ngrok 기준으로), `backend/CLAUDE.md`(외부 접속 절), 이 파일. 코드 변경 없음(문서만이라 코드 리뷰 대상 아님).
- 이 PC: ngrok 3.39.13 설치(`brew install --cask ngrok`), 인증 토큰은 ngrok 설정 파일에만 저장(저장소에는 없음). 고정 도메인은 저장소 문서에 `<고정 도메인>`으로만 적었다.

### 확인 방법과 결과
- `ngrok http --url=<고정 도메인> 8000`으로 연결. 외부 주소로 `/docs` 200, 틀린 로그인 401 `INVALID_CREDENTIALS`.
- 터널을 끄면 외부 주소는 404(ngrok 오프라인 페이지), 다시 켜면 **같은 주소**로 200.
- 외부 주소로 관리자 로그인 → 사용자 등록 → 임시 비밀번호 로그인 → 비밀번호 변경 → 질문 전송(SSE, 실제 Hermes): `session` … `done`, 조각 8개가 1.8초~2.4초에 걸쳐 끊김 없이 도착. 임시 계정은 삭제했고 개발 DB에는 `admin`만 남음.
- 브라우저 User-Agent의 POST도 ngrok 안내 페이지 없이 통과.
- 대시보드에서 요청 수와 전송량을 보는 방법과 한도, 전환 기준은 `backend/CLAUDE.md`에 적었다.
- 외부 네트워크의 휴대폰 접속: 사용자가 와이파이를 끈 휴대폰으로 `/docs`(Swagger UI)가 뜨는 것을 확인(2026-11-20).
- 확인하지 못한 것: 2분 가까운 긴 스트림(15초 keepalive가 있고 짧은 스트림만 확인), 음성 업로드가 월 전송량에 세어지는지(이슈 기준대로 사용량을 보며 확인).
