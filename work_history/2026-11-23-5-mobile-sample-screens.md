### 검토에서 정할 것
1. 입력칸 버튼: 입력이 비어 있으면 녹음 버튼, 글자가 있으면 보내기 버튼(한 자리를 바꿔 씀). 답변 중에는 중지 버튼.
2. 녹음 중 화면: 입력칸 자리가 녹음 막대로 바뀐다(빨간 점, "녹음 중", `0:42 / 2:00`, 진행 막대, 취소, 보내기). "다시 탭하면 끝내고 보낸다"를 보내기 버튼으로 표현했다.
3. 처리 중: 질문 자리에 "음성을 질문으로 바꾸는 중…"을 보여 주고, 입력칸과 녹음 버튼은 비활성. 서버에서 차례를 기다리는 동안도 같은 모습(규격: 앱은 "처리 중"으로 보여주면 된다).
4. 2분 자동 종료: 처리 중 화면 위에 "녹음이 2분이 되어 자동으로 끝내고 보냈습니다." 안내.
5. 음성 입력으로 만든 질문의 표시: 보정된 텍스트를 일반 질문과 똑같이 보여 준다(GLOSSARY "질문": 입력과 음성을 구분하지 않음).
6. (제안, 범위 밖) 음성 인식 실패 화면: 규격의 `message` "음성을 인식하지 못했습니다. 다시 녹음해 주세요."를 그대로 보여 준다. 필요 없으면 뺀다.
7. 새로 쓴 문구: "입력하거나 녹음 버튼을 눌러 말해 보세요. 지난 대화는 세션 목록에서 볼 수 있습니다."(빈 화면), "음성을 질문으로 바꾸는 중…", "녹음이 2분이 되어 자동으로 끝내고 보냈습니다.", "녹음 중", 버튼 "취소"·"보내기".
8. 웹과 다른 점: 세션 목록은 늘 메뉴 버튼으로 여는 서랍, 삭제 버튼은 늘 보임, 아이콘 버튼은 터치 최소 크기 44(`--control-minTarget-coarse`), "Enter로 보내고…" 안내 없음, 설정의 변경 버튼은 폭 전체.
9. 정하지 않은 것(구현 #32에서 다룰 후보): 마이크 권한을 거절했을 때 안내, 녹음 중 모바일 앱이 백그라운드로 갈 때 동작.

## 결과

### 확인 방법과 결과
- 토큰 검사: 샘플 `<style>`의 `var(--…)` 116개를 `@primer/primitives@11.10.0`(mobile/tool/primer_tokens의 node_modules) CSS 정의와 비교 → 모두 있음. hex 색 없음. 직접 쓴 값은 프레임 크기(390×844, 샘플 도구), 녹음 진행 막대 너비(샘플 상태 35%), `100%` 같은 레이아웃 값뿐. 질문 말풍선 최대 너비는 처음 `85%`로 썼다가 `calc(100% - var(--control-large-size))`로 바꿈.
- 렌더링 확인: Chrome headless(playwright-core)로 화면 14개 × 라이트/다크 28장. 콘솔 오류와 실패한 요청 없음. 서랍을 뺀 요소가 프레임 밖으로 넘치지 않음. 배경 라이트 `rgb(255,255,255)`, 다크 `rgb(13,17,23)`. 28장을 눈으로 확인.
