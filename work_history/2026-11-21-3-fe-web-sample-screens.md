### 검토에서 정할 것
1. 좁은 화면의 글자 크기(`ssot/PRIMER.md`에서 샘플 검토로 미룬 항목). 샘플은 Primer 토큰 설명에 있는 규칙을 따랐다. `title-large`는 좁은 화면에서 `title-medium`으로 줄이고, 본문은 그대로 둔다. 질문, 답변, 입력칸은 Primer가 "사용자가 만든 내용"용으로 정한 `body-large`(16px)를 쓴다. 16px 미만이면 iOS Safari가 입력칸을 누를 때 화면을 확대하는데, 이것도 피할 수 있다.
2. 로그아웃: `ssot/`와 기획에 정의가 없어서 샘플에 넣지 않았다. 넣을지 정해야 한다.
3. 새 세션으로 돌아가기: 새 세션은 "새로고침하면 생긴다"로만 정의되어 있다. 지난 세션을 연 뒤 새 세션으로 가려면 새로고침해야 한다. "새 세션" 버튼을 둘지 정해야 한다.
4. 샘플에서 새로 쓴 문구: "관리자에게 문의해 주세요"(차단됨), "잠시 후 다시 질문해 주세요."(서버 오류), "계정이 없으면 관리자에게 요청해 주세요."(로그인), "Enter로 보내고 Shift+Enter로 줄을 바꿉니다."(넓은 화면에만 표시), "답변을 받는 중…". 오류 문구 자체는 `openapi.yaml`의 `message`를 그대로 썼다.
5. 레이아웃 크기 토큰: 레이아웃 전용 토큰이 없어서 사이드바 너비는 `--overlay-width-small`(20rem), 채팅 폭은 `--breakpoint-medium`(48rem), 로그인 카드는 `--overlay-width-small`을 썼다.

### 확인 방법과 결과
- 토큰 검사: `@primer/primitives@11.10.0`을 `npm pack`으로 임시 폴더에 받고, 샘플의 `<style>`에서 쓴 `var(--…)` 이름을 패키지의 CSS 정의와 비교했다. 쓴 토큰 115개가 모두 있다. 값을 직접 쓴 곳은 컨테이너 쿼리 조건 `48rem` 한 곳뿐이다. 쿼리 조건에는 CSS 변수를 쓸 수 없어서 `--breakpoint-medium`과 같은 값을 직접 쓰고 주석을 달았다. hex 색은 없다.
- 렌더링 확인: Chrome headless(playwright-core)로 화면 9개 × 라이트/다크 × 넓은 화면/좁은 화면, 모두 36장을 찍어 눈으로 확인했다. 콘솔 오류와 실패한 요청은 없었다. 다크에서 화면 배경은 `rgb(13, 17, 23)`(Primer dark `bgColor-default`)였다.
- Aside 브라우저 확인(사용자 요청): Aside는 `file://`을 열 수 없어서 `python3 -m http.server 8765`로 띄운 `http://127.0.0.1:8765/index.html`에서 확인했다.
  - Primer CSS가 불러와지는지: `--bgColor-default`가 라이트 `#ffffff`.
  - 36개 조합(화면 9개 × 라이트/다크 × 넓은 화면/좁은 화면): 주소의 화면 이름, 테마, 프레임 너비(1120px / 320px), 배경색(라이트 `rgb(255,255,255)`, 다크 `rgb(13,17,23)`)이 모두 맞고, 프레임 밖으로 넘치는 요소가 없다.
  - 동작: 로그인 버튼 → 새 세션, 좁은 화면 메뉴 버튼 → 목록 열림, 닫기 버튼과 어두운 바깥 클릭 → 목록 닫힘, 세션 클릭 → 지난 세션(중단됨 표시), 삭제 버튼 → 확인 대화상자, 취소 → 대화상자 닫힘, 설정 버튼 → 설정, 빈 입력 → 보내기 버튼 비활성, 스트리밍 중 → 중지 버튼. 모두 기대대로다.
  - 키보드: 현재 세션에서 Tab을 누르면 숨어 있던 삭제 버튼에 포커스가 가고, 버튼이 보이며, 포커스 테두리(2px solid `rgb(9,105,218)`)가 표시된다.
