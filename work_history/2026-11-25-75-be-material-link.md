## 작업 내용

자료를 요청하면 Hermes가 **옵시디언에서 찾아**, 해당 파일을 **구글 드라이브에 올리고**, **링크가 있는 누구나 열 수 있게 공유**해서 링크를 답변에 넣게 한다. 없으면 없다고 답한다. 후보가 여러 개면 이름만 보여주고 어느 걸 열지 되묻는다(Claude가 정함).

### 개념 확정 (2026-11-25, 사용자)
옵시디언에서 찾기 → 드라이브에 올리기 → 링크가 있는 누구나 열 수 있게 공유 → 링크 전송. 드라이브는 자료를 찾는 곳이 아니다. `ssot/GLOSSARY.md` "자료 링크"에 반영.

### 확인한 사실 (2026-11-25, 실제 Hermes)
- 옵시디언에서 찾기(`search_files`)는 승인 없이 5초에 된다.
- 드라이브에 올리는 터미널 명령은 **보안 검사기(Tirith)** 가 "변수로 감싼 실행 파일이라 안전을 증명할 수 없다(`tirith:analysis_incomplete`)"며 승인을 요청한다. `allow_permanent=False`라 영구 허용(허용 목록)이 안 된다. Iris에는 승인할 방법이 없어 Hermes가 5분 기다린 뒤 실패한다.
- 선택: 승인을 끄면 Hermes의 모든 명령이 통과해(Slack 사용자 포함) 위험하다 → **고정된 업로드 전용 스크립트**를 직접 실행하게 해 검사기가 문제 삼지 않는지 확인한다(사용자 결정, 2026-11-25).

- [x] 링크를 클라이언트에 전달하는 방법 결정과 `ssot/`, 필요하면 `docs/api/openapi.yaml` 반영

- [x] Hermes가 그 자료를 가지고 있지 않으면 없다고 답한다.

## 설계
- `backend/hermes_tools/drive_upload.py`: Hermes의 구글 토큰(`~/.hermes/google_token.json`)으로 파일 하나를 올리고, `anyone`+`reader`(검색에는 안 잡히는 링크 공유)로 공유하고, 링크를 JSON으로 출력한다. 아무 파일이나 올릴 수 없게 **옵시디언 폴더(`~/hermes-obsidian`)와 Iris 보관함(`~/.hermes/iris-outbox`) 안의 일반 파일만** 허용한다(심볼릭 링크로 밖을 가리키는 것, 폴더, 너무 큰 파일은 거절).
- `backend/hermes_tools/drive-upload.sh`: Hermes의 파이썬 환경 경로가 업데이트로 바뀔 수 있어 구글 라이브러리가 있는 파이썬을 찾아 실행하는 고정 경로 진입점.
- 올리는 형식은 일단 원본 파일 그대로(구글 문서로 변환은 사용자 결정 전).

### 확인 방법과 결과
- 전체 테스트 통과(424개 이상). OpenAPI 린트 유효.
- 실제 Hermes: 옵시디언 찾기(`search_files`)는 승인 없이 5초. 변수로 감싼 명령으로 올리면 보안 검사기(Tirith `analysis_incomplete`)가 승인을 요청하고 영구 허용이 안 되어 5분 뒤 실패 → **고정 경로 도구를 직접 실행하게 하면 승인 없이 5~12초에 링크가 돌아옴**(사용자 결정으로 "승인 끄기"가 아니라 업로드 전용 도구로 해결, Hermes 설정은 바꾸지 않음).
- 드라이브 결과 확인: `Iris 자료/_보관함/iris-upload-test.txt`가 옵시디언 구조 그대로의 폴더에 올라가고, 공유는 "링크가 있는 누구나 보기만, 검색 불가", 소유자는 `itinnovationtf@gmail.com`. 같은 경로를 다시 올리면 덮어써서 링크가 그대로.
- 지시문을 붙인 실제 Hermes: 일반 질문은 평소처럼 답, 없는 자료는 "해당 자료를 찾지 못했습니다.", "SSOT 교육자료"는 후보 4개를 번호로 보여주고 되물음. 모두 승인 요청 없음.
- 보안 거절 확인: 옵시디언 밖 파일, `.git/config` 같은 숨김 파일, 키 파일은 올라가지 않음.
- 시험 파일은 내가 만든 것만 드라이브 휴지통으로 옮김(복구 가능). 남은 것은 `Iris 자료/_보관함/iris-upload-test.txt` 하나.
