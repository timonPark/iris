## 설계 (Claude가 정함)
- 규격은 `docs/api/openapi.yaml`을 그대로 따른다: `POST /api/v1/auth/login` 요청 `{loginId, password}`, 응답 `{accessToken, role, passwordChangeRequired}`, 오류 `401 INVALID_CREDENTIALS`, `403 ACCOUNT_BLOCKED`, 요청마다 `401 UNAUTHORIZED`, `403 PASSWORD_CHANGE_REQUIRED`. 오류 형식은 `{"error": {"code", "message"}}`. 규격에 로그인의 `422`가 빠져 있어 규격에 먼저 추가했다(`lint` 통과).
- 토큰은 JWT(`PyJWT`, HS256, 알고리즘 고정). 만료(`exp`)는 넣지 않는다. 클레임은 `sub`(계정 id), `iat`(발급 시각, 마이크로초 정밀도의 숫자). `iat`를 정수 초로 두면 같은 초에 비밀번호를 바꾼 뒤 발급한 새 토큰이 잘못 거부되므로 소수 초를 쓴다.
- 서명 키는 `.env`의 `JWT_SECRET`(32자 이상). 없거나 짧으면 앱 시작을 중단한다(로그인이 안 되는 서버가 조용히 뜨는 것을 막음).
- 요청마다 의존성(`current_account`)이 토큰을 풀고 계정을 DB에서 조회해 검사한다. 순서: 토큰 오류·계정 없음·발급 시각이 비밀번호 변경 시각보다 이름 → 401 `UNAUTHORIZED`, 차단 → 403 `ACCOUNT_BLOCKED`, 임시 비밀번호 상태 → 403 `PASSWORD_CHANGE_REQUIRED`(비밀번호 변경 API용 의존성만 이 검사를 건너뜀).
- 로그인은 비밀번호를 먼저 확인한 뒤 차단 여부를 알린다(틀린 비밀번호로 계정 존재와 차단 여부를 알아내지 못하게). 없는 아이디도 더미 해시를 검증해 응답 시간 차이를 줄인다.
- 규격에 없는 제품 엔드포인트는 만들지 않는다. 요청마다 검사는 테스트 전용 경로(`/_test/...`)로 검증한다.

### 확인 방법과 결과
- 테스트: `cd backend && uv run pytest` → 111 passed(리뷰 반영 후). 로그인 API 테스트는 실제 `iris_test` DB와 앱 시작까지 실행한다.
- **로그인 성공과 실패**: 응답 키가 정확히 `accessToken`, `role`, `passwordChangeRequired`이고 토큰이 계정 id로 풀린다. 틀린 비밀번호와 없는 아이디는 같은 401 본문. 차단된 계정은 올바른 비밀번호일 때만 403, 틀린 비밀번호는 401. 필드 누락은 422 `VALIDATION_FAILED`.
- **차단하면 토큰이 살아 있어도 거부**: 로그인으로 받은 토큰으로 200을 확인한 뒤 DB에서 계정을 차단하면 같은 토큰이 다음 요청에서 403 `ACCOUNT_BLOCKED`. 차단을 해제하면 같은 토큰이 다시 200.
- **비밀번호를 바꾸면 이전 토큰이 모두 거부**: 같은 계정으로 토큰 2개를 받고 비밀번호와 변경 시각을 바꾸면 둘 다 401 `UNAUTHORIZED`. 옛 비밀번호 로그인은 401, 새 비밀번호로 받은 토큰은 200.
- **임시 비밀번호 상태에서 다른 API 거부**: 로그인 응답의 `passwordChangeRequired`가 true이고, 일반 경로는 403 `PASSWORD_CHANGE_REQUIRED`, 비밀번호 변경용 의존성을 쓴 경로는 200. 차단된 계정은 변경용 경로에서도 거부.
- 토큰 규칙: `exp` 없음, 다른 키로 서명한 토큰·변조·서명 없는 토큰(`alg: none`)·쓰레기 값·클레임 누락·`sub`가 UUID가 아님 모두 거부, `iat`가 마이크로초 정밀도로 보존됨.
- 앱이 `JWT_SECRET` 없이(짧게) 시작하지 않음, 처리하지 못한 예외가 500 `SERVER_ERROR` 공통 형식으로 나감을 테스트.
- 실제 서버: 개발 DB의 관리자로 올바른 비밀번호 → 200(role `admin`, `passwordChangeRequired` false, 토큰에 `exp` 없음), 틀린 비밀번호 → 401, 없는 아이디 → 틀린 비밀번호와 같은 401 본문, 필드 누락 → 422.
- 규격: `npx --yes @redocly/cli@1.34.5 lint docs/api/openapi.yaml` → valid(경고 2건은 이전과 같은 의도한 값).
- 비밀값: 서명 키와 관리자 비밀번호가 `.env` 밖 파일에 없고 커밋 대상에 `.env`가 없음을 검사로 확인.
- 확인하지 못한 것: (1) 응답 시간 차이(없는 아이디도 해시 검증을 하지만 실제 시간은 재지 않음). (2) 서명 키를 바꾸면 기존 토큰이 모두 무효가 되는 것(설계상 그렇지만 직접 시험하지 않음). (3) 제품 보호 경로는 아직 없어서(세션 API는 #22), 요청마다 검사는 테스트 전용 경로로만 확인했다.

### 코드 리뷰 반영 내역
지적 9건 중 7건 반영, 2건 넘어감.
- 반영(진짜 버그): 로그인 아이디에 NUL 문자를 넣으면 500이 나는 문제. 테스트로 재현(500)한 뒤, 형식상 있을 수 없는 아이디(`LOGIN_ID_PATTERN`에 안 맞는 값)는 DB를 조회하지 않고 보통의 401로 답하게 함. 실제 서버에서도 401 확인
- 반영: 더미 해시를 처음 쓸 때 계산하던 것을 모듈을 불러올 때 만들도록 변경(첫 요청만 느려 없는 아이디를 구별할 수 있던 문제)
- 반영: 로그인이 argon2 검증 동안 DB 연결을 붙잡던 것을, 조회 후 바로 연결을 돌려주도록 변경. 검증 함수에 끼워 넣은 감시 코드로 검증 시점의 사용 중 연결 수가 0임을 테스트
- 반영: 서명된 토큰의 비정상 값(`iat`가 너무 큼 등)에서 500이 나던 것을 `InvalidTokenError`로 처리(`AttributeError`, `OverflowError`, `OSError` 추가)
- 반영: 시간대 없는 `issued_at`을 `ValueError`로 거부(서버 지역 시간으로 해석되어 비밀번호 변경 시각 비교가 어긋나는 문제)
- 반영: 변수 타입 표기(`account: Account` 등)와 쓰지 않는 `ApiError` 재노출·`__all__` 제거
- 반영: 이 작업 파일의 상태, 결과, 리뷰 내역 갱신
- 넘어감: 404/405를 공통 오류 형식으로 만들기. 규격의 오류 코드 목록에 해당 코드가 없고 규격에 없는 코드를 만들지 않음. 대신 `CLAUDE.md`의 표현을 고쳐 프레임워크 기본 응답을 쓴다고 명시
- 넘어감: `ApiModel`을 별도 모듈로 분리. 아직 쓰는 곳이 `auth.py` 하나뿐이라 두 번째 사용처가 생길 때 옮김
