## 작업 내용

Hermes가 도구를 쓰는 질문에서 `event: approval.request`(터미널 명령 실행 승인 요청, 데이터 `{"command": ...}`)를 보내면, 백엔드가 이름이 `hermes.`로 시작하는 이벤트만 건너뛰어서 그 데이터를 답변 조각으로 해석하다 `HermesError`가 난다. 이름이 붙은 이벤트는 모두 건너뛰게 고친다.

### 범위
- [x] `event:` 줄이 붙은 이벤트는 이름과 상관없이 답변이 아닌 것으로 건너뜀
- [x] 이름 없는 일반 조각, `[DONE]`, 오류 조각의 기존 동작 유지

제외: 승인 요청에 대한 처리(자동 허용 또는 거절, Hermes 설정). 보안 결정이라 별도로 정한다.

### 완료 조건
- [x] `approval.request` 등 이름이 있는 이벤트가 섞여 와도 답변 조각만 모아서 정상 완료된다.
- [x] 이름이 없는 일반 조각과 `[DONE]`, 오류 조각의 기존 동작은 그대로다.
- [x] 실제 Hermes로 도구를 쓰는 질문을 보냈을 때 오류 없이 이어진다.

### 결정 필요
없음

## 결과

### 변경한 파일
- 코드: `backend/app/hermes.py`(`_deltas`), 테스트: `backend/tests/test_hermes.py`(실제 승인 요청 모양의 데이터로 6가지 이름과 상태 초기화, `message`, `error`), 문서: `backend/CLAUDE.md`(Hermes 연동)

### 확인 방법과 결과
- 원인: 실제 Hermes 응답에서 `event: approval.request`(데이터에 `command`와 `choices` 문자열 목록)가 왔고, 백엔드는 `hermes.`로 시작하는 이벤트만 건너뛰어서 그 데이터를 답변 조각으로 읽다가 `AttributeError`→`HermesError`가 났다. 처음 쓴 테스트는 `choices`가 없어서 재현하지 못해 실제와 같은 모양으로 고쳐 재현(레드)한 뒤 고쳤다.
- 전체 테스트 404개 통과(기존 테스트 포함: 이름 없는 조각, `[DONE]`, 오류 조각, 도구 진행 이벤트).
- 실제 Hermes로 도구를 쓰는 질문(드라이브 조회, 조회만)을 고친 클라이언트로 보냄: 오류 없이 5초 만에 완료, 답변 조각 8개. (같은 질문의 원본 응답을 받을 때는 `approval.request` 뒤 `: keepalive`만 몇 분 이어지다 도구가 끝났다. 이번에는 대기가 없었다.)
- 이 확인으로 Hermes가 새 구글 계정(u2)으로 동작하는 것도 확인(드라이브에 폴더 1개).

### 코드 리뷰 반영 내역 (`/code-review medium`)
- 반영(테스트 먼저): `[DONE]`이 이름 있는 이벤트 안에 와도 스트림 종료로 처리 / 건너뛴 이벤트를 로그로 남김(`approval.request`는 경고, 명령 내용은 남기지 않음) / 경계 테스트 추가(`event:` 뒤 공백 없음, 내용이 JSON이 아닌 `error` 이벤트, 이름 있는 이벤트에서 스트림이 끝남).
- 넘어감: 승인 요청 뒤 Hermes가 기다리는 동안 `: keepalive`만 와서 읽기 제한 시간이 계속 갱신되고 답변이 몇 분 지연될 수 있는 문제(승인을 자동 허용/거절/설정 변경할지는 보안 결정이라 이 이슈 범위 밖, 한계로 `CLAUDE.md`에 적음) / 빈 줄 없는 비정상 스트림(SSE 규격 위반, 기존에도 같음) / `error` 이벤트 내용은 로그에만 남고 클라이언트에는 전달되지 않음.
